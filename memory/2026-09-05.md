## Famelack Android Media Playback Fix v1.0.4 (2026-09-05)
- **Root Cause Identified**:
  1. `PlayerScreen` did not embed `androidx.media3.ui.PlayerView` for video rendering — it only had a static placeholder column with text "▶ Streaming in background", leaving user with a black screen for live TV and webcams.
  2. `isHls = true` was hardcoded for all stream calls including direct progressive audio radio streams (MP3/AAC), causing ExoPlayer HLS extractor to throw `UnrecognizedInputFormatException`.
  3. `PlayerHolder` used `MoreExecutors.directExecutor()` instead of main thread `ContextCompat.getMainExecutor(ctx)`, which could lead to player thread access violations in Media3.
  4. ExoPlayer used default `DefaultHttpDataSource` without explicit cross-protocol redirects or mobile User-Agent, leading to 403 Forbidden or redirect drops on multiple stream CDNs.
  5. Android cleartext HTTP streams required explicit `network_security_config.xml`.
  6. YouTube Live in WebView lacked `WebChromeClient`, causing hardware-accelerated video decode issues.
- **Fixes Applied in v1.0.4**:
  1. Embedded native `androidx.media3.ui.PlayerView` in `PlayerScreen` for live video rendering with native controls.
  2. Auto-detected stream format by URI pattern (HLS only when containing .m3u8/hls, else auto-detect).
  3. Configured `DefaultHttpDataSource.Factory` with modern User-Agent, `setAllowCrossProtocolRedirects(true)`, and 15s/20s timeouts.
  4. Enforced main thread execution with `ContextCompat.getMainExecutor(ctx)` in `PlayerHolder`.
  5. Added `res/xml/network_security_config.xml` with `cleartextTrafficPermitted="true"`.
  6. Enhanced YouTube embed with `WebChromeClient`, full viewport styling, and responsive iframe.
  7. Added Reconnect button, stream URL copy, and "Open in External Player" (VLC/MPV) fallback.
- **Release**: https://github.com/3krbkbkrbrbg/famelack-android/releases/tag/v1.0.4

## Famelack Android Crash Fix v1.0.2 (2026-09-05)
- **Root Cause Identified**:
  1. AAPT was decompressing `famelack_data.json.gz` during APK packaging and renaming it to `famelack_data.json`. Code expecting `.gz` suffered an I/O mismatch / decompression error.
  2. Parsing 26MB uncompressed JSON without `largeHeap="true"` hit memory limits on startup on certain ARM64 devices.
  3. `FamelackRepository` used strict `getJSONObject("all")` which threw uncaught `JSONException` if data was still loading or structured differently.
- **Fixes Applied in v1.0.2**:
  1. Renamed compressed bundle to `famelack_data.bin` (prevents AAPT interference).
  2. Multi-strategy loading engine: checks for `famelack_data.bin` (gz), `famelack_data.json.gz` (gz), and `famelack_data.json` (plain text) dynamically.
  3. Replaced all strict JSON operations with null-safe `optJSONObject` / `optJSONArray`.
  4. Added `android:largeHeap="true"` to `<application>` in `AndroidManifest.xml`.
  5. Configured `noCompress += listOf("bin", "gz", "json.gz")` in `build.gradle.kts`.
- **Release**: https://github.com/3krbkbkrbrbg/famelack-android/releases/tag/v1.0.2
